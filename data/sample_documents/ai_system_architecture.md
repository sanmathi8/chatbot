# DocuMind AI: System Architecture & Technical Specifications

## 1. System Overview
DocuMind AI is a local, privacy-first document question-answering system using Retrieval-Augmented Generation (RAG).
The core objective is to allow organizations to query sensitive proprietary documentation completely offline without transmitting data to third-party cloud providers.

## 2. Ingestion Pipeline Specifications
- Text Splitting: Recursive character text splitting configured at 800 characters per chunk with 120 character overlap.
- Embedding Generation: Dense vector representations generated by `sentence-transformers/all-MiniLM-L6-v2` yielding 384-dimensional unit-normalized embeddings.
- Vector Indexing: ChromaDB persistent vector database configured with HNSW cosine distance metric.
- Metadata Attribution: Chunk indexes, page numbers (where applicable for PDFs), original filename, and upload timestamps are indexed alongside vector embeddings.

## 3. Retrieval & Grounding Mechanism
- Cosine Distance Threshold: Results below 0.35 similarity are filtered out to prevent hallucination.
- Top-K Selection: The top 4 most semantically relevant chunks are retrieved and formatted into an evidence block.
- Zero-Hallucination Policy: When query similarity does not meet threshold criteria, the system rejects speculation with:
  "I couldn't find sufficient information to answer this question from the uploaded documents."

## 4. Inference Engine
- Local Runtime: Ollama daemon communicating over local HTTP REST interface on port 11434.
- Target Model: Instruction-tuned local models such as `qwen2.5:3b` or `qwen2.5:0.5b` with temperature fixed at 0.2 for factual fidelity.
- Streaming: Server-Sent Events (SSE) streaming tokens to the client while returning citations.
